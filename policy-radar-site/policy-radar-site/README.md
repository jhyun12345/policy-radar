# 정책 레이더 — 설치 가이드 (코딩 몰라도 OK)

이 폴더 안 내용을 그대로 GitHub에 올리면:
- `https://[내아이디].github.io/[저장소이름]/` 주소로 누구나(링크를 아는 사람) 접속 가능한 홈페이지가 생기고
- 매주 화·수·목 오전 9시(한국시간)에 자동으로 내용이 새로고침됩니다.

총 8단계입니다. 처음 설정에 20~30분 정도 걸립니다. 한 번 해두면 그다음부턴 손댈 일이 없습니다.

---

## 1단계. GitHub 계정 만들기
1. https://github.com 접속 → 오른쪽 위 **Sign up**
2. 이메일, 비밀번호, 아이디를 입력하고 가입 완료

## 2단계. 새 저장소(repository) 만들기
1. 로그인 후 오른쪽 위 **+** 버튼 → **New repository**
2. Repository name에 `policy-radar` 입력 (원하는 이름으로 바꿔도 됨)
3. **Public** 선택 (무료 GitHub Pages를 쓰려면 Public이어야 합니다 — 아래 "주의" 참고)
4. 다른 옵션은 그대로 두고 **Create repository** 클릭

> **주의**: Public 저장소는 URL을 직접 아는 사람은 누구나 접속할 수 있습니다(검색엔진에 노출되지는 않지만, 완전한 비공개는 아닙니다). 이미 공개된 언론 보도를 정리한 내용이라 큰 문제는 없지만, 사내 전용으로 완전히 막고 싶다면 GitHub Enterprise(유료)나 사내 서버가 필요합니다 — 이건 나중에 따로 도와드릴 수 있어요.

## 3단계. 파일 업로드하기
방금 만든 저장소 페이지에서:

**(1) 일반 파일 2개 — index.html, data.json**
1. **Add file** → **Upload files** 클릭
2. 이 폴더의 `index.html`과 `data.json`을 끌어다 놓기
3. 아래 **Commit changes** 클릭

**(2) 폴더 안에 있는 파일 2개 — 경로를 그대로 입력해야 폴더가 자동으로 생깁니다**
1. **Add file** → **Create new file** 클릭
2. 파일 이름 입력칸에 `.github/workflows/update.yml` 이라고 **경로를 통째로** 입력
   (슬래시를 입력하면 자동으로 폴더가 만들어집니다)
3. 이 폴더의 `.github/workflows/update.yml` 내용을 열어서 그대로 복사해 붙여넣기
4. **Commit changes**
5. 같은 방법으로 `scripts/update-data.js` 파일도 하나 더 만들고, 내용을 복사해 붙여넣기

## 4단계. Anthropic API 키 발급받기
1. https://console.anthropic.com 접속 후 가입/로그인
2. 왼쪽 메뉴에서 **API Keys** → **Create Key**
3. 키 이름을 아무거나 적고 생성 → 화면에 뜬 키 값을 **지금 바로 복사**해서 메모장 등에 잠깐 저장
   (이 키는 한 번만 보여주고 다시는 볼 수 없습니다)
4. **Billing** 메뉴에서 결제수단을 등록하고 소액을 충전하세요
   (정확한 요금은 계정마다 다를 수 있어 console.anthropic.com의 요금 안내를 직접 확인하는 걸 추천합니다.
   웹 검색을 포함한 요청 1회 비용이라 실행할 때마다 약간의 과금이 발생한다는 점만 참고하세요.)

## 5단계. GitHub 저장소에 API 키 등록하기
1. 저장소 페이지에서 **Settings** 탭 클릭
2. 왼쪽 메뉴 **Secrets and variables** → **Actions**
3. **New repository secret** 클릭
4. Name: `ANTHROPIC_API_KEY` (정확히 이 이름으로)
5. Secret: 4단계에서 복사해둔 키 값 붙여넣기 → **Add secret**

## 6단계. GitHub Pages 켜기 (홈페이지 주소 만들기)
1. 저장소 **Settings** → 왼쪽 메뉴 **Pages**
2. **Source**를 **Deploy from a branch**로 설정
3. **Branch**를 `main`, 폴더는 `/ (root)` 선택 → **Save**
4. 1~2분 기다리면 페이지 상단에 `https://[내아이디].github.io/policy-radar/` 같은 주소가 나타납니다
   이 주소를 사내 사람들에게 공유하면 됩니다.

## 7단계. 자동화가 잘 도는지 테스트하기
1. 저장소 **Actions** 탭 클릭
2. 왼쪽에서 **정책 레이더 자동 업데이트** 워크플로 선택
3. 오른쪽 **Run workflow** 버튼 → 다시 **Run workflow** 클릭 (수동 실행)
4. 1~2분 후 초록색 체크가 뜨면 성공입니다. 빨간 X가 뜨면 로그를 열어 오류 메시지를 확인하세요
   (대부분 API 키를 잘못 등록했을 때 발생합니다 — 5단계를 다시 확인)
5. 성공했다면 저장소의 `data.json` 파일이 방금 새로 갱신된 걸 볼 수 있고, 홈페이지 주소로 가면
   "마지막 자동 업데이트" 시각이 방금으로 바뀌어 있을 겁니다.

## 8단계. 이후엔 그냥 두면 됩니다
- 매주 화·수·목 오전 9시(한국시간)에 자동으로 실행됩니다.
- 실행 기록은 언제든 **Actions** 탭에서 확인할 수 있습니다.
- 실행 요일/시간을 바꾸고 싶으면 `.github/workflows/update.yml` 파일 안의 `cron` 값 3줄을 수정하면 됩니다.
- 내용을 급하게 수동으로 고치고 싶다면 저장소에서 `data.json`을 직접 열어 편집해도 됩니다
  (다음 자동 실행 때 다시 덮어써진다는 점만 기억하세요).

## 9단계. 담당자 제보 채널 만들기 (선택, 하지만 추천)
현장에서만 아는 일정(예: "다음주 수요일에 ㅇㅇ부처에서 뭔가 발표한다던데")을 자동 업데이트에
반영하고 싶다면, GitHub의 **Issue(이슈)** 를 채팅창처럼 씁니다.

1. 저장소 상단 메뉴에서 **Issues** 탭 → **New issue** 클릭
2. 제목은 자유롭게(예: "일정 제보함"), 내용은 비워둬도 됨 → **Submit new issue**
3. 이슈 생성 후 화면 오른쪽의 **Labels** 톱니바퀴 아이콘 클릭 → `radar-tips` 라는 이름의
   라벨을 새로 만들고 이 이슈에 붙이기 (라벨 이름은 정확히 `radar-tips`여야 스크립트가 찾습니다)
4. 이제 이 이슈 화면 맨 아래 댓글창에, 알고 있는 내용을 편하게 채팅하듯 적으면 됩니다.
   예: "다음주 수요일쯤 기재부에서 뭔가 발표 준비 중이라고 들었음, 확실친 않음"
   "OO장관이 이번주 금요일에 지역 순회 일정 있다고 들었는데 아직 기사는 안 남"
5. 여러 사람이 같은 이슈에 댓글을 계속 달아도 되고, 각자 새 이슈를 만들어 `radar-tips`
   라벨만 똑같이 붙여도 됩니다.
6. 다음 자동 실행(화/수/목 9시) 때 스크립트가 이 댓글들을 모두 읽어서 리서치에 참고합니다.
   확정 사실이 아니어도 괜찮습니다 — 실제 검색으로 교차 확인한 뒤 반영하도록 되어 있습니다.
7. 다 반영됐다 싶은 댓글은 나중에 직접 지워서 정리해도 되고, 그냥 둬도 스크립트가 알아서
   맥락 판단해 걸러냅니다.
8. **홈페이지에서도 바로 갈 수 있게 연결하기**: 3번에서 만든 이슈를 브라우저에서 열면 주소창에
   `https://github.com/아이디/저장소이름/issues/숫자` 형태의 링크가 보입니다. 이 주소를 복사해서
   `index.html` 안의 `https://github.com/YOUR_GITHUB_USERNAME/YOUR_REPO_NAME/issues/1` 부분을
   그대로 바꿔치기하면(Ctrl+F로 찾기), 홈페이지 상단 **"📝 일정 제보 남기기"** 버튼을 눌렀을 때
   바로 그 댓글창으로 이동합니다.

### 제보를 남긴 날, 화·수·목까지 안 기다리고 바로 반영하고 싶다면
평소엔 화·수·목 자동 실행에 맡겨두고, 제보를 새로 남긴 날처럼 바로 반영하고 싶을 땐
**Actions 탭 → 정책 레이더 자동 업데이트 → Run workflow** 버튼을 누르면 즉시 한 번 더 실행됩니다
(7단계에서 테스트할 때 눌렀던 바로 그 버튼입니다). 홈페이지에 "새로고침" 버튼을 따로 만들지 않은
이유는, 그 버튼을 아무나 누를 수 있게 열어두면 방문자가 계속 눌러 API 요금이 의도치 않게 청구될
수 있기 때문입니다. Actions 탭의 버튼은 저장소 접근 권한이 있는 사람만 누를 수 있어 더 안전합니다.

## 자동 리서치가 놓치지 않도록 챙기는 것들
- **일정 상세화**: "9.15 청문회"가 아니라 "9.15(화) 오전 10시, 국회 법제사법위원회, ㅇㅇ후보자 인사청문회"처럼
  시간·장소·소관 위원회까지 채우도록 지시해뒀습니다.
- **담당자 제보 반영**: 위 9단계에서 만든 `radar-tips` 이슈의 댓글을 매번 읽어와서, 실무자만 아는
  정보를 "미확인 제보"로 프롬프트에 넣고 웹 검색으로 교차 확인하도록 되어 있습니다. 확인이 안 되면
  "(담당자 제보 기반, 공식 확인 필요)"라고 표시된 채로 낮은 확신도로 포함됩니다.
- **이익단체·시민단체 집회, 정당 자체 행사**: 노조 파업 예고, 직능단체 궐기대회, 정당 보고대회 등은
  일반 정치 뉴스가 아니라 업계지·정당 보도자료에 먼저 나오는 경우가 많아, 검색 카테고리에 따로 넣어뒀습니다.
- **기념일·정례 발표·확정된 원거리 일정**: 국군의날, 참사 주기, 부처의 정례 발표일(예: 저PBR 명단 공표,
  국가교육발전계획 시안 발표, 우주발사체 발사일 등)처럼 날짜가 이미 정해진 일정은 2~3주 범위를 벗어나더라도
  최대 5주까지 주차를 늘려서 포함하도록 지시해뒀습니다. 억지로 일정을 당겨 적지 않고, 필요하면 주차를
  하나 더 만들어 보여줍니다.
- **지난 업데이트 대비 진전 표시**: 매번 실행할 때 직전 `data.json`을 함께 읽어서, 같은 이슈가
  어떻게 진전됐는지("청문회 → 임명 강행" 등)를 자동으로 비교해 문구에 반영하도록 지시해뒀습니다.

## 자동 리서치 품질 관리 (v2) — 왜 3단계로 바꿨나
이전에는 AI에게 "검색하고, 정리하고, JSON까지" 한 번에 시켰는데, 아래 오류가 반복됐습니다.
**① 지난 카드를 고쳐 쓰다 틀린 내용이 이월** ② **작년·재작년 기사가 올해 것처럼 섞임** ③ **기사 제목만 보고 사실처럼 작성** ④ **요일·날짜 계산 실수, 주장과 무관한 출처 링크**.

지금은 매 실행마다 처음부터 아래 순서로 새로 조사합니다.
1. **리서치**: 국회/정부/집회·노조/정당/기념일·확정일정/사회이슈/담당자 제보를 카테고리별로 따로 조사. 검색어에 연·월을 넣고, 기사 발행일·본문 확인 여부·주장 주체(야당 주장 등)를 기록.
2. **작성**: 1단계 근거 목록만으로 카드를 새로 작성. 이전 판 문구는 복사하지 않음.
3. **독립 검증**: 별도 호출이 카드마다 날짜·수치·출처를 다시 검색해서 확인, 안 되면 약화하거나 삭제.
4. **코드 검증**: (AI가 아니라 프로그램이) 요일을 달력과 대조해 자동 수정, 이번 실행에서 실제로 검색되지 않은 URL과 작년 날짜가 박힌 URL 제거, 출처가 없는 카드는 "재확인 필요" 표시.

카드 상단에 **확인됨 / 보도 기준 / 제보·미확인 / 재확인 필요** 배지가 붙고, `data.json`의 `quality` 항목과 Actions 로그에 수정·제거 내역이 남습니다.
근거가 너무 적거나 카드가 5개 미만이면 **기존 data.json을 덮어쓰지 않고 실패 처리**합니다(전 판은 `data.prev.json`에 백업).
실행 시간은 이전보다 길어져(약 10~25분) 워크플로에 45분 제한을 두었습니다. API 사용량도 늘어나니 첫 달은 Anthropic 콘솔에서 비용을 확인하세요.

## 문제가 생기면
- **홈페이지에 "데이터를 아직 불러오지 못했습니다"가 뜬다**: `index.html`과 `data.json`이 저장소 최상위(같은 폴더)에 있는지 확인하세요.
- **Actions 실행이 빨간 X로 실패한다**: Actions 탭에서 실패한 실행을 눌러 로그를 열면 원인이 영어로 적혀 있습니다. 그 내용을 복사해서 저(클로드)에게 붙여넣어 주시면 원인을 같이 찾아드릴게요.
- **카드 색이나 문구 톤을 바꾸고 싶다**: `index.html` 상단의 `:root { ... }` 안 색상 값을 바꾸면 전체 색이 바뀝니다.
